# Decisions

Choices made while building corpus-graph, including where the implementation departs from the brief and why. Answers given to the one batch of clarifying questions are marked **(asked)**.

## Scope answers (asked)

- **Default extraction model: Sonnet** (`claude-sonnet-5-5` via `--model sonnet`). Override per run with `--model opus` / `--model haiku`.
- **Languages: EN, DE, FR, IT.** Book abbreviation tables cover all four; the extraction prompt asks for original-language terms as aliases; the scholar normaliser handles particles (von, van, de, di, della…).
- **marker-pdf is an optional extra** (`uv sync --extra marker`). Without it, poor-yield PDFs are kept with `meta.quality.poor = true` and a note telling you to install it.
- **Obsidian: frontmatter + vault export.** `work/md/*.md` carry YAML frontmatter and a `## Footnotes` section; `corpus-graph export-vault` writes a vault with one note per node and `[[wikilinks]]`.

## Departures from the brief

1. **Schema extended where the brief's schema left node types unreachable.** As written, `AncientAuthor`, `Place` and `Period` had no edge types at all, so they would always be isolated nodes. I made three minimal, documented extensions in `canon/schema.yaml`:
   - `discusses` may also target `Object`, `Place`, `Period`, `AncientAuthor` (not only `Concept`);
   - `about` may also target `Object`, `Place`, `Period`; `grounded_in` may also target `Object` (a claim resting on a papyrus or ostracon);
   - `attributed_to: PrimaryText → AncientAuthor`, *derived deterministically* from the locus tables (confidence `inferred`), never extracted by the LLM.
   Everything else the extractor wants still goes to `work/schema_proposals.json`. Remove the extensions in `canon/schema.yaml` if you prefer the strict schema.
2. **There is no Document→Scholar relation for citing a scholar.** The brief's schema only has `written_by`. The extractor repeatedly tries `Document -cites-> Scholar`; those edges are rejected and logged in `work/resolve_rejected.json`. Scholar co-citation in the report is computed from *mentions* (provenance) instead, so nothing is lost, but if you want "cites scholar" as an explicit edge, add it to the schema (see README).
3. **Canon has more registries than the five listed**: `places.yaml`, `periods.yaml`, `arguments.yaml` (every node type gets one), plus `documents.yaml` (metadata overrides), `merges.yaml` (merge decisions) and `schema.yaml`.
4. **Merge approvals are stored in `canon/merges.yaml`, not only in `work/proposed_merges.json`.** `work/` is disposable cache; your decisions should survive deleting it. You can still approve by editing `status` in the JSON: the next `resolve` copies the decision into `canon/merges.yaml`.
5. **`unresolved: true` means "identity not settled"**, not "not in a registry". It is set for: citations the locus parser could not read, surname-only scholar references that match several scholars and whose years do not decide, items matching several registry entries, and any node that is a member of a pending merge proposal. A concept seen once and not registered is resolved (by normalisation) but appears in `work/canon_candidates/` for you to register. Otherwise nearly every node would be "unresolved" before you curate, and the viewer toggle would be useless.
6. **Quotes are verified, not just required.** An item is kept only if its quote is found in the chunk after whitespace/punctuation/hyphenation normalisation, or (for OCR noise) with ≥ 92 rapidfuzz partial-ratio. Paraphrased quotes are rejected and logged in `work/rejected.jsonl`. Over-long quotes are cut to their first 25 words (still verbatim) and flagged `truncated`.
7. **Communities are detected on the entity graph, not the full graph.** With Document nodes included, Leiden mostly rediscovers "the things one article mentions". By default documents are removed, entities are linked by their typed edges plus a co-mention weight (1/(k−1) for k entities in the same chunk), and documents are then placed in the community of most of their neighbours. `build --community-mode full` restores the naive behaviour.
8. **The sample runs on recorded responses.** The three sample articles were extracted once with the live `claude -p` backend (Sonnet, 2026-10-29); the responses are committed in `sample/fixtures/` and replayed by `make sample` and the tests (`--backend replay`). `make sample-live` re-extracts and refreshes them.

## Pipeline details

- **Hashing / idempotence.** Every stage is keyed by the source file's SHA-256. `ingest` skips unchanged files (and records `ingest_version`); `extract` caches per chunk under a key of (prompt version, schema, header, chunk text, attached footnotes); `resolve`/`build`/`report` are cheap and always recompute. Sources are opened read-only.
- **PDF conversion.** pymupdf4llm 2.0's layout engine (`pymupdf.layout`) classifies boxes; `page-header`/`page-footer` boxes are dropped (running heads), `footnote` boxes are moved to `## Footnotes`, with a backstop for notes the model misclassifies (small type, bottom third, starts with a number). Superscript note markers become `[^n]`. When headers/footers carry a consistent page number, journal pagination is used (`<!-- page 101 -->`), otherwise PDF page numbers.
- **Poor-yield heuristic** (falls back to marker-pdf): chars/page < 400, or "word-like" token ratio < 0.55 (Latin, Greek and Hebrew letters count as word-like, so polytonic Greek is not penalised), or > 0.5 % undecodable glyphs (`(cid:`, U+FFFD, private use area), or > 60 % of lines under 20 characters (column interleaving). Not applied to DOCX/Markdown. Legacy Greek fonts (SuperGreek, SPIonic) produce Latin-letter garbage that *passes* these tests; see "Known limitations".
- **DOCX** is read directly from the OOXML (no extra dependency): headings from paragraph styles, italics, real footnotes from `footnotes.xml`, page markers from Word's `lastRenderedPageBreak` (approximate).
- **Unicode.** All text is NFC-normalised; comparison keys strip combining marks (so δηνάριον = δηναριον, Schürer = Schurer) but stored text never changes.
- **Chunking.** Sections are split at `#`–`###` headings and packed to ~6,000 tokens (UTF-8 bytes ÷ 4, which weights Greek/Hebrew appropriately); an oversized section is split at paragraph breaks. Each chunk gets the footnotes it references (or, when markers are missing, the notes of the pages it covers), and the title/authors/year/venue/abstract header.
- **Locus parser.** Colon = chapter:verse with comma-separated verses; comma = chapter,verse (DE/FR/IT) with full-stop-separated verses (`Mk 6,37.39`); full stop = chapter.verse with commas; `;` continues the same book; `f.` = +1 verse, `ff.` = open range (treated as +2 verses for overlap); verse letters (37a) collapse to the verse; Talmud folios keep their side (83a). A number is only a locus if it is plausible for the book (so "Mark 2004" is not Mark chapter 2004). Short abbreviations that differ between languages are decided by the document's detected language (e.g. "Gn" Genesis in French, Jonah in Italian). Locus granularity is as cited: `Luke 15:8` and `Luke 15:8–10` are separate nodes; queries use overlap, so "Luke 15" finds both.
- **Scholar resolution.** Registry exact/alias → registry by surname (+ initial, + publication years) → corpus groups by surname + first initial (split further when two different full first names share an initial) → surname-only references attach to the unique candidate, or by year when several share the surname, or become an `…-ambiguous` node with a proposal. Document authors from metadata are added as scholars with `written_by` edges, so authorship never depends on the LLM.
- **Fuzzy matching** runs only between nodes of the same type that are not both registry entries: `token_sort_ratio ≥ 78` for Arguments, `WRatio ≥ 88` otherwise. `resolve --llm-merge` asks the LLM to annotate each candidate as same/different/unsure; nothing is applied until you approve.
- **Report.** Betweenness is exact up to 2,500 nodes and sampled (k = 500) above. "Heavily cited" for co-citation = cited by at least max(2, 75th percentile) documents; a pair is a surprise when cited together in 1–2 documents while each is cited elsewhere, ranked by how far below the independence expectation the co-citation falls. Contested passages = a PrimaryText grounding an Argument that is both argued and disputed, or grounding rival Arguments whose proponents have a `disagrees_with` edge. All quotes shown are ranked: the claimant's own article first, then quotes naming both endpoints.
- **Viewer.** Canvas rendering (SVG does not survive 3,000 nodes), D3 7.9.0 vendored and inlined (no network), graph inlined as JSON so `out/index.html` also works from disk. Above 3,000 visible nodes it collapses to a community graph with drill-down. Large layouts are pre-settled before the first frame. Provenance links open `/source/<hash>?line=N` when served (line-numbered Markdown, scrolled to the line) and the Markdown file when opened from disk.
- **Logging.** Every LLM call goes to `work/llm_log.jsonl` (backend, model, purpose, doc, chunk, chunk tokens, tokens in/out, cache read/write, cost, duration, error). The pre-run cost estimate fits output tokens per chunk from this log once three live calls exist.
- **No telemetry, no network** except the LLM backend. `claude -p` is run from an empty temporary directory with tools, MCP servers, settings files and slash commands disabled.

## Arch / CachyOS packaging

- **No AUR, and no mixing of system and pip Python packages.** `leidenalg` is AUR-only and `pymupdf4llm` imports only with the exact PyMuPDF it was released with, which Arch's `python-pymupdf` is not, so the package installs the `uv.lock` set (hash-checked) into `/opt/corpus-graph/lib`. Only build tools and optional extras come from pacman.
- **Bundled CPython by default.** A rolling-release Python minor upgrade would otherwise orphan the compiled wheels. `CORPUS_GRAPH_PYTHON=system makepkg` uses `/usr/bin/python3` instead and installs a pacman hook that warns when a rebuild is needed.
- **Built from committed `HEAD`** (`git archive`), so the package is reproducible from a commit; makepkg's `check()` runs the sample pipeline through the packaged launcher.
- **User configuration is never edited silently.** `corpus-graph-setup` only touches niri and Noctalia configs when asked (`--niri`, `--noctalia`), appends a marked block once, and backs up niri's `config.kdl`.
- **Theme via a Noctalia user template** rendered to `~/.config/corpus-graph/theme.css`, which the viewer re-reads on focus; it uses Material colour roles (`surface`, `on_surface`, `primary`, `outline_variant`, …) in the `{{colors.<role>.default.hex}}` form shared by Noctalia v4 and v5 templates.
- **Workspace lookup** now also reads `CORPUS_GRAPH_ROOT` from `~/.config/corpus-graph/config` when the current directory is not a workspace, so launcher actions, the systemd unit and terminal use agree on one workspace.

## Known limitations

- **Legacy-encoded Greek** in older PDFs (pre-Unicode fonts) comes out as Latin gibberish that the yield heuristic cannot detect. Such files need OCR (marker-pdf) or re-sourcing. Check `work/md/` for Greek passages after the first real ingest.
- **Locus tables are finite.** Unknown abbreviations become `pt:unparsed:*` nodes flagged unresolved; add the work to `canon/primary_texts.yaml` under `works:`.
- **Argument identity is the weakest link.** The prompt pushes for canonical phrasing, but the same claim still comes out in several wordings across chunks and articles. Expect to spend most curation time approving Argument merges (`corpus-graph merges list --type Argument`, `merges approve --min-score 90 --type Argument` for the obvious ones).
- **An `…-ambiguous` scholar node pools all unresolvable references to that surname**; approving it into one person moves all of them. If they belong to different people, add both people to `canon/scholars.yaml` with their publication years instead.
- **Anthropic SDK backend** is written against the documented structured-outputs API but was not exercised here (no API key in the build environment); the `claude -p` backend was tested live.
